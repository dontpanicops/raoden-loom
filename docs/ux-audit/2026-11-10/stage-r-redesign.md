# Этап R — редизайн «Calm depth + стекло»

Ревизия 3, 2026-11-10. Третий круг скептика: блокирующих нет. Утверждена владельцем 2026-11-10 (§5). Ревизии 1–2 разобрали скептик (2 круга) и критик, сводка
правок — §8.

## 1. Цель и источники

Перевести интерфейс Raoden Loom на новую визуальную систему:
- объём через уровни поверхности 0–4;
- стекло только на плавающем хроме;
- 4 темы.

Попутно закрыть находки аудита 2026-10-05 (Н1–Н14).

Форматы журналов, доски, канвы и `board-*/v1` не меняются. Команды main тоже не меняются. Исключения перечислены
явно:
- поле `bend` связи и новый IPC-вызов `setLinkBend` (R2); команды запуска не меняются;
- поля настроек `reduceTransparency`, `onboardingDismissed`, `followSystem` (R0, R2, R4);
- поле `appearance.theme` в контексте плагинов (R0);
- цвета окна и стартовой страницы main, высота шапки и `trafficLightPosition` (R0, R1).

Источники, все лежат в `docs/ux-audit/2026-11-10/`:
- **Макеты Claude Design** — источник вида: цвета, уровни, отступы, компоновка. Файлы:
  - `redesign/SPEC.md`;
  - `redesign/tokens.css`;
  - `redesign/components-reference.css`;
  - `redesign/preview/` — JPEG в репозитории; полный набор `redesign/shots/` хранится только локально, 203 МБ.
- **Код** — источник поведения и текстов. Расхождения макета с кодом собраны в `spec-vs-code.md`, по ним прав код.
  Тексты пауз берутся из `orchHeadline_*`, `orchPause_*`, `orchReason_*`, `orchError_*`
  (`src/renderer/src/lib/i18n.ts`). Действия — только команды `OrchestrationRunCommand`
  (`src/shared/orchestration.ts:165–189`) в пределах допусков `apply()` (`orchestrationService.ts:2633–2760`, наборы
  `268–274`).
- **Дефекты выгрузки макетов** — `shots-qa.md`.
- **Исправления макета панели и дефектов** — `claude-design-prompt-3.md` (ожидается от Claude Design).

Какой источник главнее, когда они расходятся:
1. код;

## 2. Правила для всех подэтапов

- **Порядок:** R-pre → R0 → R1 → R2 → R3a → R3b → R4. Каждый подэтап — ветка `feat/r<n>-…` от свежего main и
  отдельный PR. Merge делает владелец после зелёного CI. Следующий подэтап начинается после слияния.
- **Каждый PR:**
  - `npm test`, `npm run typecheck`, `npm run build`;
  - `npm run lint:ci` — предупреждений не больше базы R-pre (267 на 2026-11-10);
  - smoke из «Готово, когда» подэтапа;
  - скриншоты «было / стало» в `docs/ux-audit/<дата>/r<n>/`;
  - `node scripts/contrast-check.mjs` без нарушений (скрипт появляется в R0);
  - ревью диффа агентом с чистым контекстом, до 3 кругов. Если после 3-го круга остались блокирующие замечания,
    подэтап останавливается и идёт к владельцу;
  - раздел «Как сделано» в этом файле: отступления, проверки с числами, откат.
- **Если smoke или CI красный,** причина ищется по коду. Ожидания тестов меняются только для инвариантов, явно
  названных в подэтапе как «меняется осознанно».
- **Без модельных вызовов.** Smoke только на подставных CLI. Упакованные smoke с реальным codex app-server не
  запускаются.
- **`UI_CONTRACT.md` и `UI_CONTRACT.ru.md`** правятся в том PR, где меняется строка контракта (таблица §6).
- **Иконки** только Lucide. Марки провайдеров не меняются. Над нативным браузером нет оверлеев. Честность данных
  (UI_CONTRACT «Status, sessions and launch») сохраняется.
- **Новых npm-зависимостей нет.**
- **`backdrop-filter`** только на уровнях 3–4: шапка окна, полоса пространств, панель запуска, тосты, мини-карта, меню,
  палитра, модалки. На карточках холста его нет.
- **Литералы цветов.** В `src/renderer` литералы допустимы в четырёх местах:
  - `styles/tokens.css`;
  - марки и цвета провайдеров;
  - данные: `CANVAS_REGION_COLORS` и пользовательские цвета HOME — это сохраняемые значения;
  - два цвета `readableTextColor` (`App.tsx:162–166`) и цвета превью выбора фона/темы/HOME в Настройках
    (`SettingsPanel.tsx:98–107, 400–402, 443–458`) — превью показывает значение токена, а токен на `.app` в этот момент
    другой.

  Всё остальное пишется на семантических токенах.

   - Тип: `OrchestrationAgentLink.bend?: {along:number, across:number} | null` (`src/shared/orchestration.ts:549`).
   - Точка изгиба: `P = M + along·(T−F) + across·|T−F|·n̂`. Здесь F — порт лида, T — порт исполнителя, M — середина
     FT, d = T−F, n̂ = (−d.y, d.x)/|d| в экранных координатах (y вниз). Кубическая кривая: C1 = F + ⅔(P−F),
     C2 = T + ⅔(P−T). При |d| < 1px изгиб не применяется.
   - `along` и `across` лежат в [−2, 2]. `null` или отсутствие поля — автоматическая кривая: `along=0`, `across`
     подбирается так, чтобы кривая обходила карточки.
   - `canvasStore.setLinkBend(linkId, bend)`: проверка `Number.isFinite` и диапазона, `null` — сброс. `busy` не
     требуется. Плюс IPC, preload и клиент.
   - Сохраняется на pointerup. Во время жеста кривая рисуется локально.
   - Отрисовка: кубическая кривая, стрелка к исполнителю, ручка у выбранной связи, бегущий пунктир при «ждёт». При
     `prefers-reduced-motion` пунктир неподвижен.
   - **Чип связи** стоит в точке кривой при t=0.5, смещён по n̂ от карточек (Н14). На чипе конкретная причина паузы
     последнего запуска (Н1). При нескольких живых запусках связи (до 4) чип показывает «N запусков» и самый
     требовательный статус.
   - Формат канвы `v:1` не меняется. Поле необязательное; `canvasStore.load` и `save` сохраняют лишние поля
     (`canvasStore.ts:121–128, 164`).
6. Мини-карта, зум, подсказки клавиш — уровень 3.
7. **Контракт** — строки §6, помеченные R2.
