### 2.3 Стекло над тёмным холстом в светлой теме (главная работа)

Тот же приём, что R1 для тёмных тем над светлыми холстами (`tokens.css:~435`): составные правила
`.app--paper.app--canvas-night`, `...canvas-graphite`, `...canvas-stone`, `...canvas-lilac` (и то же для frost)
поднимают `--surface-3/-4` плотность. Оценка по расчёту: для paper над night/graphite нужна альфа поверхности 3
около .94 и поверхности 4 около .96 (как R1 для linen/mist); над stone/lilac — .80/.88. Значения подбирать по
`contrast-check` итеративно (скрипт уже умеет составные правила: `compound = blocks(/^\.app--(sand|bay|paper|frost)\.app--canvas-.../)`).
Обязательно:
- двойной класс `.app--reduce.app--reduce` остаётся последним (`tokens.css:446`), иначе «меньше прозрачности» перестанет
  перебивать (так уже сделано для тёмных; новые составные правила тоже должны быть ниже);
- по факту при альфе .94 светлая теме над тёмным холстом выглядит почти как непрозрачная — это ожидаемо; «стекло»
  в светлой теме над тёмным холстом — компромисс. Решение владельцу не нужно, зафиксировать в «Как сделано»;
- альтернатива отвергнута: ограничить сочетания (запретить тёмные фоны холста в светлой теме) — ломает независимость
  фона холста от темы (Р3, §6 контракта).

### 2.4 Терминальная палитра

`--term-*` и `--ansi-*` в paper/frost определены и проходят порог 3 (исключения `white`/`bright-white` как фон по
замыслу ANSI для светлых тем). Риск не в токенах, а в: (1) `--term-selection` на светлом фоне (полупрозрачный, проверить
читаемость выделения на кадре); (2) `bright-black` как «dim» текст приложений (vim/less) на светлом фоне — порог 3, не 4.5,
по спеке; (3) пересчёт `terminal.options.theme` только при смене пропа `palette`: с followSystem проп должен быть
действующей темой (§2.6), иначе терминал остаётся старым. Тест `terminal-lifecycle` проверяет связь `--term-bg` и
`options.theme.background`: расширить на paper и frost (по образцу smoke-r0-tokens).
