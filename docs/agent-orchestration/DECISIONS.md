# Журнал решений

Решения этапов до R записаны в спецификациях этапов (`implementation/`) и в разделах «Решено» планов; этот журнал
ведётся с этапа R (редизайн интерфейса, спека `docs/ux-audit/2026-11-10/stage-r-redesign.md`).

## D-001 — Этап R режется на подэтапы, каждый — отдельный PR и слияние после зелёного CI (2026-11-10)
Статус: принято
Решение: R-pre → R0 → R1 → R2 → R3a → R3b → R4 → R4.1, ветка `feat/r<n>-…` от свежего main; следующий подэтап после
слияния предыдущего. Сливает оркестратор сам после `gh pr checks` = зелёный (поручение владельца).
Почему: маленькие PR проходят ревью за 1–2 круга; откат по одному подэтапу.
Альтернативы: один большой PR — отвергнут (ревью RunPanel.tsx на 2000+ строк).
Что заставит пересмотреть: конфликтующие правки между подэтапами.

## D-002 — Р9 распространено на push_protected (2026-11-11)
Статус: принято
Решение: в паузах, где main из кнопок принимает только stop (STOP_ONLY и вариант needs_user_action/push_protected),
главная кнопка зоны — «Остановить запуск».
Почему: показывать главной кнопку, которую main отклонит, — ложное обещание.
Альтернативы: главной — локальная «Посмотреть изменения» (макет) — отвергнуто.

## D-003 — «Следовать системе» без миграции настроек (2026-11-11)
Статус: принято
Решение: поле `followSystem` (по умолчанию false) добавлено без смены `SETTINGS_VERSION` (16). При светлой системе —
paper, при тёмной — sand. Ручной выбор плитки выключает следование.
Почему: новое поле со значением по умолчанию не требует миграции, откат на 1.5.20 его отбрасывает.
Цена: откат на 1.5.20 и сохранение там настроек превращают paper/frost в sage — выбор теряется.

## D-004 — Тема до первого кадра читается в main из settings.json (2026-11-11)
Статус: принято
Решение: main синхронно читает `settings.json` до создания окна (`earlyTheme`, при ошибке — sand) и передаёт тему в
`backgroundColor`, стартовую страницу и URL рендерера (`?theme=`). `nativeTheme.themeSource` не выставляется.
Почему: без этого светлая тема мигает тёмным первым кадром.
Остаётся: вспышка при перезагрузке окна после смены темы (в URL стартовая тема).

## D-005 — Мини-карта: полупрозрачна в покое, клики перехватывает (2026-11-11)
Статус: предварительно
Решение: `opacity .5` в покое, 1 при наведении, фокусе и перетаскивании; резерв места и сдвиг не делались.
Почему: простое решение, не трогает геометрию холста и тест `minimap-geometry`.
Что заставит пересмотреть: жалобы, что карточку под мини-картой не достать.

## D-006 — Внутренний редизайн форм панели запуска — отдельный PR R4.1 (2026-11-11)
Статус: принято
Решение: формы PersonDecide, PlanProposal, FinishConfirm переделываются после слияния R4 отдельным PR.
Почему: `RunPanel.tsx` > 2000 строк, R3a и R3b потратили на нём круги ревью; смешивать с темами и доской — риск.

## D-007 — Боковые цветные полосы убираются везде (2026-11-11)
Статус: принято
Решение: акцент тона — рамка по периметру (и свечение только у «Ждёт вас») плюс цвет метки или глифа; полосы слева
(`inset 4px 0 0`, `border-left`) не используются.
Почему: владелец назвал их «нейро-слоп»; в макете Claude Design (`redesign/preview/07-run-panel-*`) полос нет —
это было отклонение реализации R3b от макета.

## D-008 — После R4.1 — сверка всего редизайна с макетами Claude Design (2026-11-11)
Статус: принято
Решение: каждый кадр `docs/ux-audit/2026-11-10/redesign/preview/*.jpg` (57 кадров, 19 экранов) сравнивается с живым
кадром приложения в том же состоянии и теме; расхождения — список с path:line, исправления отдельным PR, пары
«макет / приложение» в `docs/ux-audit/`. Осознанные отклонения, записанные в спеке, остаются.
Почему: требование владельца — редизайн должен соответствовать макетам.

## D-009 — Приёмка интерфейса по парам «макет / приложение» (2026-11-11)
Статус: принято
Решение: с R5 подэтап интерфейса готов, только когда для каждого затронутого экрана лежит пара кадров макета и
приложения в той же теме, визуальный ревьюер сверил пары, лид посмотрел пары сильных экранов. Отклонение от макета —
только записью D-NNN до коммита. После этапа — полная повторная сверка.
Почему: сверка 2026-11-11 нашла 76 расхождений при зелёных тестах; разбор причин —
`docs/ux-audit/2026-11-10/conformance/why-drift.md`.

## D-015 — Зона действия R5a: что как в макете, что нет (2026-11-11)
Статус: принято
Решение (по умолчанию — макет, D-009):
- «Уточнить» в зоне только там, где она есть в макете: план на проверке («Уточнить задачу») и подозрение на цикл;
  в остальных паузах команда доступна из вкладки «Ход работы» (макет 13).
- «Один шаг» в зоне подозрения на цикл не показывается (макет 09).
- В плане на проверке — только «почему», без второго абзаца «Подходит — начните…» (макет 04); тест на непустой
  «что делать» для этой паузы снимается.
- Не делаем, нет данных или команды: «Выгрузить ревью» у завершённого запуска; код выхода и выдержка ошибки у
  упавшего (нет в `cause`, нужна правка main и IPC — отдельно).
- «Открыть журнал» вместо макетного «Открыть лог»: вкладка называется «Журнал», термин один.

## D-016 — HOME и первый запуск после R5c (2026-11-11)
Статус: принято
Решение:
- Раскладка HOME по умолчанию (сетка 16×12, минимум контракта 12×8) не меняется под пропорции макета 8×4; размеры
  плиток и шрифтов подогнаны под зум 0.67.
- Карточка первого запуска рядом с HOME занимает доступную ширину (компактная раскладка при < 480 px по спеке);
  камера ради 560 px не сдвигается.
- Подвал первого запуска ссылается на пункт «С чего начать» палитры ⌘K — пункт добавляется в R5e (макет 10).
- Подписи статусов терминала и агента — по макету («Ждёт ввода», «Свободно», «Упал», «Вышел · код N») — в R5d вместе
  с CardStatus, глобально.
- Строки лимитов без процента (процент в aria-label и подсказке), заголовок без «· неделя»: окна лимитов у
  провайдеров разные.
- Подсказки клавиш — три строки под мини-картой (Home, F2, ⌘K); подсказки колеса и навигации — в блоке «Управление
  холстом» первого запуска и в UI_CONTRACT.
